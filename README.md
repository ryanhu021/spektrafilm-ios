# spektrafilm for iOS

A Swift port of [spektrafilm](https://github.com/andreavolpato/spektrafilm), Andrea Volpato's
spectral simulation of analog photography. It takes a scene-linear image, exposes it onto a virtual
film emulsion, prints it through a virtual colour enlarger onto paper, and scans the result, all in
spectral space from published datasheet measurements.

> **Status: engine in progress.** The colour foundations, profile loading and the parity harness are
> done and gated. The model, pipeline stages and editor UI are not written yet, so there is no
> working render on device. See [Status](#status).

## Why a port and not a wrapper

The reference implementation is Python and NumPy, which will not run on iOS. Rather than reimplement
the model from its physics, this port reproduces the reference's arithmetic and gates every stage
against fixtures generated by it, pinned to one upstream commit. The goal is a render that matches
spektrafilm, not one that merely looks filmic.

There is also an [Android port](https://github.com/thetechgeekko/Spektrafilm-android) under active
development. It is prior art, consulted for the problems it has already solved, but it is never the
numeric source of truth; the Python reference is.

## Layout

```
Sources/SpektraFilm/     Engine. No third-party dependencies, builds for iOS and macOS.
  Core/                  Buffers, matrices, interpolation, errors.
  Colour/                Colourspaces, transfer functions, illuminants, observers.
  Profiles/              Profile types and the bundled-profile loader.
  Generated/             Tables extracted from colour-science. Do not edit by hand.
  Resources/             28 film and paper profiles, the spectral LUT, filter curves.
Tests/SpektraFilmTests/  Parity tests and their committed fixtures.
App/                     iOS app. project.yml is the source of truth; the .xcodeproj is generated.
Tools/parity/            Fixture generator, table extractor, oracle setup.
```

## Build and test

Engine, on macOS:

```sh
swift build
swift test
```

App, needing [XcodeGen](https://github.com/yonaskolb/XcodeGen):

```sh
brew install xcodegen
make project   # generates App/Spektrafilm.xcodeproj
make app       # builds for the simulator
```

`make help` lists every target.

## Parity

Every numeric claim is checked against fixtures produced by the reference implementation at
upstream commit
[`3bb2c2d`](https://github.com/andreavolpato/spektrafilm/commit/3bb2c2d2801ff68b92019cf1dbcbb133d60832bc).
Fixtures are committed, so CI runs the gate without Python. The tolerance is `max_abs <= 1e-4` and
`rms <= 1e-5`, matching the contract the Android port settled on. Stochastic stages (grain, glare)
cannot match a different RNG bit for bit and are gated on their statistics instead.

Regenerating fixtures needs the oracle, which is a local checkout of upstream at the pinned commit:

```sh
make oracle     # clones upstream at the pin, builds a Python 3.13 venv
make goldens    # regenerates the fixtures
make tables     # regenerates Sources/SpektraFilm/Generated
```

A changed fixture means the render changed. Review the delta rather than committing it.

The reference render of 18% grey through Portra 400 onto Portra Endura, in sRGB, is
`[0.4607145, 0.46055124, 0.46038181]`. That is the anchor the end-to-end gate will use.
